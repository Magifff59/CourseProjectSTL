# 🏗 База-ґрунт-фундамент команд для роботи у терміналі

* **Зібрати ВСІ ФАЙЛИ в один exe**
    ```bash
    g++ src/main.cpp src/logger.cpp -o logger_app
    ```

* **Запуск проги**
    ```bash
    ./logger_app
    ```

---

## 🛠 Команди для роботи з GIT

* **Додати файли до змін**
    ```bash
    git add .
    ```
    *(крапочка в кінці свідчить, що будуть додані УСІ файли в чергу на збереження)*

* **Збереження чекпоінтів (комітів)**
    ```bash
    git commit -m "Feat/Fix etc.: опис того, що зробив"
    ```

* **Переглянути історію збережень**
    ```bash
    git log --oneline
    ```

* **ВІДКАТ ДО ОСТАННЬОГО ЧЕКПОІНТУ (якщо все пішло не за планом)**
    ```bash
    git restore .
    ```
    *(крапочка в кінці означає, що УСІ файли повернуться до стану останнього коміту)*

---

### 🔧 Рихтування факапів у назвах комітів

* **Якщо помилились або забули префікс в ОСТАННЬОМУ коміті:**
    ```bash
    git commit --amend -m "Feat/Fix etc.: опис"
    ```

* **Якщо треба перейменувати старіші коміти (глибше в історію):**
    1. Виконати команду:
       ```bash
       git rebase -i HEAD~3
       ```
       *(де 3 — кількість комітів, які хочеш переглянути, до прикладу)*
    2. У вікні, що відкриється, заміни слово `pick` на `reword` (або просто `r`) біля потрібного коміту.
    3. Зберегти та закрити файл і Git запропонує ввести новий текст.

## 📂 Структура проєкту (на цей момент)

* **`include/`** — «Мозок» проєкту, де є заголовкові файли (`.h`) у яких описується структура класів та оголошуються методи.
    * `logger.h` — декларація класу Logger.
* **`src/`** — «М'язи» проєкту, де лежать файли реалізації (`.cpp`).
    * `logger.cpp` — детальна логіка роботи всіх функцій лоґеру.
    * `main.cpp` — точка входу, де йде тестування функціоналу.
* **`logger_app.exe`** — Готовий застосунок. 
* **`logs.txt`** — «Щоденник», куди лоґер автоматично записує всі події після завершення роботи програми.
